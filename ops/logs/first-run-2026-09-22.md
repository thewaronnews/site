## Script/Worker mismatches found and fixed (script changed, not the Worker)

1. **`wayback.py` called a nonexistent endpoint.** It GET'd
   `/admin/sources/without-wayback`, which does not exist —
   `site/src/admin.js` / `linkstate.js` expose only `GET /admin/sources/due`,
   `POST /admin/sources/checks` and `POST /admin/sources/<id>/wayback` (spec
   section 8). Fixed the default batch mode to use `/admin/sources/due`
   (filtered locally for a missing `wayback_url`), matching the Worker.

2. **No admin endpoint lists "all sources."** `/admin/sources/due` is scoped
   to `last_checked` unchecked-for-≥20h, so on a same-day re-run (this run:
   sources were already checked once during seed load, at a synthetic
   `last_checked` a few hours old) it returns 0 rows — useless for a
   "classify/backfill everything now" pass, and it can't discover sources a
   same-day `linkcheck.py` run just touched either. Added `--all` to both
   `linkcheck.py` and `wayback.py`: reads the public, unauthenticated
   Frictionless export at `/data/json/sources.json` (spec 4.5, refreshed via
   `POST /admin/export`, operator scope) instead. Ordinary nightly runs
   should omit `--all` and keep using `/admin/sources/due` as designed.

3. **`wayback.py` crashed the whole batch on the first source.** The
   Worker's `setWayback` (`linkstate.js`) requires `wayback_url` to match
   `^https://web\.archive\.org/`, but archive.org's own availability API
   (`archive.org/wayback/available`) answered with `http://web.archive.org/…`
   on every call observed this run. The Worker correctly rejected it (422
   `must_be_web_archive_org`), and the uncaught `AdminAPIError` killed the
   run after source 1. Fixed `wayback.py` to upgrade the scheme to `https://`
   before posting. Also wrapped both `client.post(...)` calls in `run_batch`
   in try/except so one bad POST logs and continues instead of aborting the
   whole batch — this wasn't strictly a Worker mismatch, but the failure
   mode (one row kills 98 others) was clearly not intended.

## Environment-only issues (no script/Worker change needed, or fixed with a local workaround)

- **`linkcheck.py` Tier 2 (Playwright) failed outright in this sandbox**:
  `launch(headless=False)` needs a real X server (by design — a headed
  browser is meant to evade headless-detection on the Mac Studio where this
  normally runs). Worked around with `xvfb-run -a`, no script change; all
  Tier-2 checks then completed normally.
- **`common.JevClient` (used by both `linkcheck.py` and `newsdesk.py`) was
  blocked outright by the Jev demo endpoint's Cloudflare WAF** — every call
  403'd with `error code: 1010`. Reproduced directly: a request with no
  explicit `User-Agent` (Python's default `Python-urllib/3.x`) is blocked;
  the identical request with a browser UA succeeds. This is a real script
  bug (not sandbox-specific — any non-browser default UA would trip it), so
  **fixed in `common.py`**: `JevClient.classify()` now sends `common.CHROME_UA`.
  This was high-impact: before the fix, linkcheck's Jev-ambiguous pages and
  100% of newsdesk's Jev candidate scoring were failing.
- **Nieman Lab's RSS feed has a leading newline before the XML declaration**
  (`b'\n<?xml version="1.0"...'`), which `ET.fromstring` rejects even though
  the feed is otherwise well-formed. Fixed `newsdesk.py`'s `fetch_feed` to
  strip leading whitespace/BOM before parsing.
- **Wayback's Save Page Now was degraded for most of this run**: the
  majority of failures were `ConnectionResetError` / TLS EOF while POSTing
  to `web.archive.org/save/…`, plus a directly-reproduced `HTTP 520` from
  the same endpoint for one URL tested by hand. The agent proxy's own status
  endpoint independently logged repeated `ws_closed_mid_exchange` /
  `connect_rejected` entries for `web.archive.org:443` during this window.
  This reads as an external capacity/connectivity issue, not a script or
  Worker bug; no fix applied beyond retrying per the existing 8-consecutive-
  failure/resume design.
